# Личный VPN: WireGuard + VLESS/Reality

Свой VPN для себя: один небольшой сервер (VPS) и приложение на ваших устройствах.
Весь трафик устройства идёт через сервер, провайдер и публичные Wi-Fi видят только зашифрованный поток.

В репозитории два протокола, которые ставятся на один и тот же сервер и не мешают друг другу:

| Протокол | Порт | Когда использовать |
|---|---|---|
| **WireGuard** | UDP 51820 | Быстрый и простой. Подходит там, где VPN не блокируют (Украина, Грузия) |
| **VLESS + Reality** (Xray) | TCP 443 | Маскируется под обычное HTTPS-соединение с чужим сайтом. Нужен там, где WireGuard режут (Беларусь) |

| Файл | Назначение |
|---|---|
| `server/install.sh`, `server/vpn-client.sh` | WireGuard: установка и команда `vpn-client` |
| `server/install-reality.sh`, `server/vless-client.sh` | VLESS+Reality: установка и команда `vless-client` |
| `tests/` | Тесты (без реального сервера) |

## Какой протокол для какой страны

Обстановка по открытым источникам на 2025–2026 годы, она может меняться. Правовой статус VPN в вашей стране я не проверял, уточните местные правила.

- **Беларусь.** Во время блокировок в январе 2025 года у пользователей переставали работать многие VPN-сервисы: DPI провайдеров распознаёт рукопожатия WireGuard и OpenVPN, а часть протоколов с маскировкой (например, AmneziaWG и Psiphon) продолжала работать
  ([Новая газета Европа](https://novayagazeta.eu/articles/2025/01/25/v-belarusi-nakanune-vyborov-nachalis-pereboi-v-rabote-vpn-i-nekotorykh-saitov-news),
  [Euroradio](https://euroradio.by/en/disruptions-vpn-services-and-websites-have-begun-belarus)).
  Ставьте **VLESS+Reality**. WireGuard оставьте как запасной вариант.
- **Украина и Грузия.** По открытым данным, массовой блокировки VPN там не отмечено (блокируются отдельные сайты), поэтому обычного WireGuard достаточно. Reality можно не ставить, но ничего не мешает поставить и его.
- Если ездите между странами или нужен один набор настроек на все случаи, поставьте оба протокола на один сервер.

## Что понадобится

- **VPS** с Ubuntu 22.04/24.04 или Debian 12, виртуализация KVM (не OpenVZ/LXC), публичный IPv4.
  Самый дешёвый тариф подойдёт (1 vCPU, 512 МБ–1 ГБ RAM): обычно **около $4–6 в месяц**, актуальную цену смотрите у хостера.
- **Расположение сервера: за пределами Беларуси**, лучше в Европе (Польша, Литва, Германия, Финляндия): близко к Беларуси и Украине, для Грузии задержка будет выше, но для обычного использования приемлема.
  Сервер внутри Беларуси брать не стоит: он под местной юрисдикцией и теми же блокировками.
- Проверьте правила хостера: часть провайдеров запрещает VPN/прокси в условиях использования.
- Домен и платные подписки не нужны.

## Установка (5–10 минут)

Репозиторий приватный, поэтому клонировать его на сервер по HTTPS нельзя (спросит пароль). Скопируйте папку `server`
со своего компьютера, где репозиторий уже склонирован:

```bash
scp -r server root@IP_СЕРВЕРА:/root/vpn-server
ssh root@IP_СЕРВЕРА
cd /root/vpn-server
```

Затем на сервере поставьте нужное (`phone` замените на имя своего устройства, например `iphone`):

```bash
# VLESS+Reality (Беларусь)
FIRST_CLIENT=phone bash install-reality.sh

# WireGuard (Украина, Грузия, запасной вариант)
FIRST_CLIENT=phone bash install.sh
```

Каждый скрипт поставит пакеты, сгенерирует ключи, запустит службу с автозапуском и сразу покажет QR-код (для Reality ещё и ссылку `vless://`) для первого устройства.

Если у хостера есть облачный файрвол (в панели управления), откройте в нём **TCP 443** (Reality) и/или **UDP 51820** (WireGuard).

Необязательные параметры (переменные окружения перед `bash ...`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `REALITY_PORT` | `443` | TCP-порт Reality |
| `REALITY_SNI` | `www.microsoft.com` | сайт-прикрытие (должен поддерживать TLS 1.3 и HTTP/2) |
| `REALITY_ENDPOINT` / `WG_ENDPOINT` | определяется сам | публичный IP сервера |
| `WG_PORT` | `51820` | UDP-порт WireGuard |
| `WG_NET_PREFIX` | `10.8.0` | внутренняя подсеть WireGuard `/24` |
| `WG_DNS` | `1.1.1.1, 9.9.9.9` | DNS для клиентов WireGuard |
| `FIRST_CLIENT` | нет | сразу создать клиента с этим именем |

Установщик Reality использует официальный скрипт [XTLS/Xray-install](https://github.com/XTLS/Xray-install), он скачивается с GitHub во время установки.

## Подключение устройств

### VLESS+Reality

1. Установите приложение с поддержкой VLESS+Reality (список приложений меняется, проверяйте наличие в магазине вашей страны):
   - Android: **v2rayNG** или **Hiddify**;
   - iOS и macOS: **Streisand**, **V2Box** или **Hiddify**;
   - Windows и Linux: **Hiddify** или **v2rayN** (Windows).
2. На сервере: `sudo vless-client add имя`. Появятся ссылка `vless://…` и QR-код.
3. В приложении: «Добавить из буфера обмена» (скопируйте ссылку) или «Сканировать QR-код».

### WireGuard

1. Установите официальное приложение **WireGuard** (iOS, Android, Windows, macOS, Linux).
2. На сервере: `sudo vpn-client add имя`. Появится QR-код.
3. В приложении: «Добавить туннель» → «Сканировать QR-код». Включите туннель.

Для ноутбука без камеры: `sudo vpn-client show имя`, скопируйте конфиг в файл `имя.conf` и импортируйте его.

### Команды управления

```bash
sudo vless-client add|show|list|remove NAME   # VLESS+Reality
sudo vpn-client   add|show|list|remove NAME   # WireGuard
```

Для каждого устройства создаётся свой ключ, поэтому потерянный телефон можно отозвать (`remove`), не трогая остальные.
`vless-client add/remove` перезапускает Xray, и активные соединения обрываются примерно на секунду.

## Как проверить, что всё работает

Включите туннель и откройте https://ifconfig.me: должен показаться IP вашего сервера.
На https://dnsleaktest.com не должно быть DNS вашего обычного провайдера.
В WireGuard IPv6 внутри туннеля намеренно не используется (весь IPv6-трафик клиента заворачивается в туннель и там блокируется), поэтому утечки по IPv6 нет.

## Безопасность

- QR-код, ссылка `vless://` и `.conf` клиента **содержат ключи доступа**: не отправляйте скриншоты, не публикуйте в чатах.
- Входите на сервер по SSH-ключу и отключите вход по паролю (`PasswordAuthentication no` в `/etc/ssh/sshd_config`).
- Включите автообновления: `apt-get install -y unattended-upgrades`.
- Делайте резервную копию `/etc/wireguard` и `/usr/local/etc/xray` (иначе после переустановки придётся заново выдавать ключи).
- Сервер видит ваш трафик так же, как раньше видел провайдер. VPN переносит доверие к вашему провайдеру на хостера. Логи доступа в Xray выключены, в WireGuard их нет, но «no-logs» тут обеспечиваете вы сами, ничего не включая.
- Reality-сервер блокирует исходящие соединения в частные сети и на metadata-сервис хостера (`169.254.169.254`), чтобы клиент не мог добраться до внутренней сети.

## Ограничения

- **Reality не гарантирует обход блокировок.** Он маскирует протокол, но не IP: если цензор заблокирует IP-адрес вашего сервера (или целую подсеть хостера), нужно менять IP или хостера. Сайт-прикрытие (`REALITY_SNI`) лучше выбирать из популярных и не заблокированных в вашей стране.
- WireGuard в Беларуси может не работать вовсе, это нормально, для этого и добавлен Reality.
- Один сервер = одна страна выхода. Для нескольких стран нужно несколько VPS.
- Скорость ограничена каналом и трафиком тарифа VPS (проверьте лимит у хостера).
- Альтернатива Reality для Беларуси: AmneziaWG (обфусцированный WireGuard), в этом репозитории не реализован.

## Тесты

```bash
sudo apt-get install -y wireguard-tools qrencode shellcheck jq openssl python3 curl
shellcheck server/*.sh tests/*.sh
bash tests/test_client.sh                       # WireGuard: конфиг сервера и клиенты

# Reality: нужен бинарник xray (скачайте релиз XTLS/Xray-core с GitHub)
XRAY_BIN=/путь/к/xray bash tests/test_reality.sh   # конфиг, ключи, ссылки, клиенты
XRAY_BIN=/путь/к/xray bash tests/e2e_reality.sh    # реальный туннель на localhost
```

Сквозной тест `e2e_reality.sh` запускает настоящие Xray-сервер и Xray-клиент, настроенный по ссылке `vless://` из `vless-client`, и проверяет три вещи:
трафик проходит через туннель, с неверным публичным ключом не проходит, доступ к частным адресам через туннель закрыт.

Скрипты `install.sh` и `install-reality.sh` целиком (пакеты, systemd, сеть) проверены только статически и по частям: генерация конфигов и работа клиентов покрыты тестами,
а полную установку нужно запускать на реальном сервере. Если что-то не заработает, пришлите вывод скрипта.
